# 発散モード

目的は**良い案を出すこと**ではなく、**選択肢の空間を広げること**。良し悪しの判断は次のモード（`/converge`）の仕事。

## モード契約（破ったら発散になっていない）

1. **生成中は評価しない。** 「ただし現実的には」「これはコストが高い」を書かない。批評の一文が入った瞬間に発散は止まる。
2. **推奨しない・順位をつけない。** 最後に「おすすめは」と言わない。
3. **同じ案の言い換えを並べない。** 粒度違い・表現違いは1案とみなす。
4. **量を出す。最低12案。** 足りないと感じたら案をひねり出すのではなく、**軸を足す**。
5. 制約は**別枠に書き出す**。制約に反する案も消さず、`[制約違反: 予算]` と印をつけて残す。制約自体が間違っている可能性を潰さないため。

## 手順

### 1. 問いを広げる（解より先に）
元の問いを **How might we 〜** 形で3通りに再定義する。抽象度を1段上げたもの、1段下げたもの、対象をずらしたものを各1つ。
以降の発散は「元の問い」だけでなく、この3つの問いすべてに対して行う。

### 2. 発散軸を4〜6本立てる
案をひねり出すのではなく、軸を選んで機械的に埋める。テーマに合うものを選ぶ:

| 軸 | 問いかけ |
|---|---|
| スケール | 極小版は？ 100倍版は？ |
| 時間 | 今日できるのは？ 3ヶ月版は？ 3年版は？ |
| 主体 | 自分でやる / 他人にやらせる / 自動化する / ユーザーにやらせる / やらない |
| 制約反転 | 予算ゼロなら？ 予算10倍なら？ 締切が明日なら？ 締切がないなら？ |
| アナロジー | ゲーム業界なら / 医療なら / 物流なら / 個人商店なら どう解くか |
| 前提破壊 | 「必ずXである」の X を1つずつ消したら何が可能になるか |
| 逆張り | 普通と正反対をやったら？ |

各軸で2〜4案。**1案1行**、動詞で始める。説明は書かない。

### 3. ワイルドカード枠（必ず3つ）
- 一見バカげている案を1つ
- **何もしない**案を1つ（現状維持の価値を必ず俎上に乗せる）
- **問題そのものを消す**案を1つ（そもそもこれを解く必要があるか）

### 4. 掛け合わせ（3つ）
既出の案から2つずつ選んで組み合わせる。番号で示す（例: `#3 × #11 → …`）。単独では弱い案がここで化けることが多い。

## 出力形式

```
## 問いの再定義
1. HMW ...
2. HMW ...
3. HMW ...

## 案
### 軸: <軸名>
1. ...
2. ...
### 軸: <軸名>
...

## ワイルドカード
13. （バカげた案）...
14. （何もしない）...
15. （問題を消す）...

## 掛け合わせ
- #3 × #11 → ...

## 制約メモ
- 制約: ...（違反している案: #4, #9）

次: /converge で絞り込み、/devils-advocate で本命案を叩けます。
```

## アンチパターン

- 案が全部「同じ方向のグラデーション」になっている → 軸が1本しかない
- 実装手順やスケジュールを書き始める → それは収束
- 「バランスの取れた案」を出す → 発散に中庸は不要。端を取れ
- 案が5個で止まる → 質のフィルタが無意識に働いている。軸を足して機械的に埋める
