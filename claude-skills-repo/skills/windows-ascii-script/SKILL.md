# windows-ascii-script

Windows上で実行するPowerShell/バッチスクリプトを生成・編集する際に、CP932(Shift-JIS系)
コードページとの衝突による文字化け・実行時エラー、および `curl` コマンドの実体が
`Invoke-WebRequest` のエイリアスにすり替わっていることによる事故を防ぐためのスキル。

## なぜ起きるか

- Windows(特に日本語版)のコンソールはデフォルトでコードページ932(CP932/Shift-JIS)
  を使用する環境が多く、LLMが生成するUTF-8前提のスクリプト(全角文字、絵文字、
  スマートクォート `’ “ ”`、em dash `—`、矢印 `→` などを含む)を保存・実行すると、
  文字化けやパースエラー、最悪の場合スクリプトの一部が別のコマンドとして解釈される
- PowerShellには `curl` という**エイリアス**が標準で存在し、これは実体が
  `Invoke-WebRequest` であって本物の `curl.exe`(BSD/curl互換)ではない。
  オプション体系もレスポンスの扱いも異なるため、`curl -s -o file.json url` のような
  Unix流のワンライナーをそのまま書くと壊れる

## 適用タイミング

- `.ps1` / `.bat` / `.cmd` ファイルを新規作成・編集するとき
- Windows上で動かすことを前提としたスクリプト(GitHub APIやローカルLLMサーバーへの
  リクエスト、ファイル操作、ビルドスクリプトなど)を生成するとき
- 生成したスクリプトをそのままファイルに保存して実行する運用のとき(貼り付けて手動実行
  ではなく、エージェントが直接ファイルへ書き出すケースは特に注意)

## 手順

### 1. スクリプト本文を純ASCIIに保つ

- コメント・メッセージ文字列を含め、**全角文字・日本語・絵文字・スマートクォート・
  em dash・全角矢印を一切使わない**。日本語で説明が必要な場合は、スクリプト本体には
  英語コメントのみを書き、日本語の説明はスクリプトの外(チャット上やREADME)で行う
- 引用符は半角の `'` `"` のみを使う。Markdown生成時に自動変換されがちなスマート
  クォートが混入していないか、生成後に確認する
- 記号は `->` `=>` `--` のようなASCIIの組み合わせで代替する(`→` `—` は使わない)

### 2. 保存エンコーディングを明示する

- Windows PowerShell 5.1(`powershell.exe`)は既定でBOM付きUTF-8を期待する場合がある
  一方、PowerShell 7(`pwsh.exe`)はBOMなしUTF-8でも動く。対象がどちらか不明な場合は
  **BOM付きUTF-8**で保存するのが安全側
- バッチファイル(`.bat`/`.cmd`)はUTF-8を正しく解釈しないことが多いため、ASCIIのみ
  で完結させるか、スクリプト冒頭に `chcp 65001 > nul` を入れてコードページを切り替える
- 改行コードはCRLFを基本とする(LFのみでも動く場合が多いが、`.bat`は特に要注意)

### 3. `curl` ではなく `curl.exe` を明示的に呼ぶ

```powershell
# NG: PowerShellのエイリアス(Invoke-WebRequest)が呼ばれ、オプションが通らない
curl -s -o release.json https://api.github.com/repos/OWNER/REPO/releases/latest

# OK: 本物のcurlバイナリを明示的に指定する
curl.exe -s -o release.json https://api.github.com/repos/OWNER/REPO/releases/latest
```

- 同様に `wget` なども別名解決の対象になりうるため、外部コマンドを呼ぶ際は
  `Get-Command <name> -All` で実体を確認する習慣をつける
- PowerShellネイティブに寄せたい場合は `Invoke-RestMethod` / `Invoke-WebRequest` を
  素直に使い、`curl` という名前を経由しない選択肢も検討する

### 4. GitHub API等の外部APIを叩くPowerShellパターン

```powershell
# ASCII only, explicit encoding, explicit curl.exe
$ErrorActionPreference = "Stop"
$Uri = "https://api.github.com/repos/OWNER/REPO/releases/latest"
$OutFile = "release.json"

curl.exe -s -H "Accept: application/vnd.github+json" -o $OutFile $Uri

if (-not (Test-Path $OutFile)) {
    Write-Error "Download failed: $OutFile not found"
    exit 1
}

$Release = Get-Content $OutFile -Raw | ConvertFrom-Json
Write-Host "Latest tag: $($Release.tag_name)"
```

- `Invoke-RestMethod` を使う場合はこちら(こちらはPowerShellネイティブなので
  `curl.exe`問題は発生しないが、プロキシ設定やTLSの挙動が異なる点に注意):

```powershell
$ErrorActionPreference = "Stop"
$Uri = "https://api.github.com/repos/OWNER/REPO/releases/latest"
$Release = Invoke-RestMethod -Uri $Uri -Headers @{ "Accept" = "application/vnd.github+json" }
Write-Host "Latest tag: $($Release.tag_name)"
```

### 5. 生成後のセルフチェック

スクリプトを保存する前に、以下を確認する。

- [ ] 全角文字・絵文字・スマートクォート・em dash・全角矢印が含まれていないか
      (`Select-String -Pattern '[^\x00-\x7F]'` でASCII範囲外の文字を検出できる)
- [ ] `curl` を素で呼んでいる箇所がないか(`curl.exe` になっているか)
- [ ] `.bat`/`.cmd` の場合、UTF-8前提の文字列がないか、`chcp 65001` を入れたか
- [ ] パス区切りが `\` と `/` で混在していないか(PowerShellは両方許容するが、
      `cmd.exe` 経由のコマンドには `\` を使う)
- [ ] 環境変数参照がPowerShell流(`$env:VAR`)とcmd流(`%VAR%`)で混在していないか

### 6. 検出コマンド例

```powershell
# ASCII範囲外の文字を含む行を検出
Get-Content .\script.ps1 | Select-String -Pattern '[^\x00-\x7F]'

# curl の実体を確認
Get-Command curl -All
```

## よくある失敗パターン(実例ベース)

| 症状 | 原因 | 対処 |
|---|---|---|
| スクリプト実行時に文字化け・構文エラー | 全角文字/スマートクォートがCP932環境で誤解釈 | 本文を純ASCIIに統一 |
| `curl -o file url` が謎のエラーで失敗、またはHTMLがそのまま出力される | `curl` が `Invoke-WebRequest` のエイリアスとして解決されていた | `curl.exe` と明示 |
| GitHub APIのレスポンス取得後、`ConvertFrom-Json` がコケる | ダウンロード時のエンコーディング破損 | `curl.exe` 使用 + `-Raw` でファイル読み込み |
| ローカルLLMサーバー向けスクリプトが特定環境でだけ動かない | PowerShell 5.1/7の既定エンコーディング差 | BOM付きUTF-8で保存、対象バージョンを明記 |

## 備考

- Docker上のLinuxコンテナ経由でWindows GPUワークロード(RTX 4070 Ti等)を動かすより、
  ネイティブWindows実行を前提とする場合に本スキルの対象となる場面が多い
- native Windows実行環境(PowerShell 5.1/7混在、日本語コードページ)を前提とした
  スクリプト生成全般に適用する
