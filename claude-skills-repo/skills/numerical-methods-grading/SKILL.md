# 数値計算法2026 課題採点スキル

数値計算法2026の講義課題(L1〜L15など)を、採点基準の作成から学生ごとの採点、Moodle用
成績CSVの作成、採点結果報告書の作成まで一気通貫で行うためのワークフロー。第8回課題(L8)の
採点で確立した方式を汎用化したもの。

## 前提: フォルダ構成

ユーザーのデスクトップ上、`数値計算法2026` フォルダの下に講義回ごとのサブフォルダがある:

```
数値計算法2026/
  L<N>/
    <課題PDF>                                    例: 08_連立１次方程式の解法_その1.pdf
    評定-数値計算法(...)-第N回課題-....csv         Moodleの成績入力用CSV
    数値計算法(...)-第N回課題-.../                 学生提出物フォルダ(Moodle形式)
      <氏名>_<参加者ID>_assignsubmission_file/<ファイル>
  CLAUDE.md                                       プロジェクト全体の運用ルール(下記参照)
```

作業を始める前に、プロジェクトルートの `CLAUDE.md` を読むこと。そこに採点方針・減点基準・
過去の決定事項が記録されている(このスキルの `references/late_penalty_policy.md` はその要約)。
`CLAUDE.md` と本スキルの内容が食い違う場合は、より新しい情報である `CLAUDE.md` を優先し、
ユーザーに確認する。

## 全体の流れ

1. **入力の確認**: 対象講義回のフォルダ(課題PDF・CSV・提出物フォルダ)をユーザーのデバイスから
   `device_list_dir` で確認し、`device_stage_files` でこのセッションにステージングする。
2. **採点基準のドラフト作成**: 課題PDFを読み、演習・小問ごとの配点案を作る。二層構成
   (提出点50点+内容点50点)と、`references/late_penalty_policy.md` の遅延減点表を必ず使う
   — これはL8でユーザーが明示的に承認した固定ポリシーであり、講義回ごとに再提案する必要はない。
   配点の内訳(演習の数・小問の重み)は課題ごとに異なるので、PDFの内容に応じて都度設計する。
   `scripts/build_rubric_docx.js` 用の `rubric_config.json` を組み立て、スクリプトを実行して
   docx化する(スクリプト冒頭のコメントにJSONスキーマと例あり)。LibreOffice+pdftoppmで
   レンダリングして目視確認してから、`SendUserFile` でユーザーに送り、**内容を承認してもらって
   から次のステップに進む**(承認を待たずに採点を始めない)。
3. **採点の実行**: `references/grading_agent_prompt_template.md` の方式に従い、学生1人につき
   1体の `Agent` サブエージェントを並列に立ち上げて採点する。出力は同ファイルで定義した
   JSONスキーマに統一し、こちらでパースして集約する(自由形式Markdownのパースは過去に
   フォーマット揺れで漏れが起きたので避ける)。
4. **点数の計算**: 集約結果を `grading_input.json` の形に変換し、
   `python scripts/compute_grades.py grading_input.json computed_grades.json` を実行して
   提出点・内容点・合計点(遅延減点込み)を計算する。
5. **成績CSVの更新**: `python scripts/update_csv.py <元のMoodle CSV> computed_grades.json <出力CSV>`
   で、Moodleの成績CSVに評点と採点ワークフローステータスを埋める(未提出者は自動で0点になる)。
   フィードバックコメント欄は使わない(空にする) — これはユーザーが明示した標準方針。
   採点ワークフローステータスは、既定値「未採点」を、判断が確定した行はすべて「採点完了」に、
   `flag`(手順3のJSON出力の `flag` フィールド、例:「要学生確認」)が付いた学生だけ
   「採点中」に更新する(未提出者は0点で判断が確定しているので「採点完了」)。
6. **採点結果報告書の作成**: 前段で確定した `computed_grades.json` を `report_data.json` の形に変換し、
   `node scripts/build_summary_docx.js report_data.json <出力docx>` で、学生別採点結果一覧
   (合計点順、要確認事項は赤くハイライト)・統計(平均/最高/最低/中央値)・未提出者一覧を含む
   報告書docxを作る。
7. **納品**: 生成した成績CSVと報告書docxを `SendUserFile` で送り、`device_commit_files` で
   ユーザーのデバイスの該当 `Lxx` フォルダに保存する。**このスキルの採点はAIによる一次採点で
   あり、Moodleへ反映する前に人間による確認が必要**であることを、報告書本文とユーザーへの
   返信の両方で必ず明記する。

## 途中で確認を取るべきポイント

- 手順2の採点基準は、必ずユーザーの承認を得てから採点(手順3以降)に進む。ユーザーが
  「よい」「これで進めて」のように明確に肯定するまで待つ。
- 遅延提出者がいて、`references/late_penalty_policy.md` の区分に当てはまらない特殊なケース
  (例: 7日超で「要相談」に該当する学生)がいる場合は、機械的に減点せず、必ずユーザーに
  どう扱うか確認する。
- 提出物に欠落・不整合がある学生(ファイル形式の相違、内容の食い違いなど)は、独断で0点や
  満点を付けず、`flag`/`note` で報告書に残し、人間の判断を仰ぐ形にする。

## バンドルされているファイル

- `scripts/build_rubric_docx.js` — 採点基準docxを生成(入力: `rubric_config.json`)
- `scripts/compute_grades.py` — 提出点+内容点+遅延減点から合計点を計算
  (入力: `grading_input.json`)
- `scripts/update_csv.py` — Moodle成績CSVに評点・コメントを埋める
- `scripts/build_summary_docx.js` — 採点結果報告書docxを生成(入力: `report_data.json`)
- `references/late_penalty_policy.md` — 遅延減点の標準ポリシー(段階的減点表)
- `references/grading_agent_prompt_template.md` — 学生別採点サブエージェントの
  プロンプト設計方針とJSON出力スキーマ

各スクリプトの入力JSONの正確なスキーマは、スクリプトファイル冒頭のコメントに書いてある
(使う直前にそこを読むこと。ここでは重複させない)。
