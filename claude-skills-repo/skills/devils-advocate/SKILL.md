# 悪魔の代弁者モード

目的は**批判すること**ではなく、**壊れるかどうかを確かめること**。壊れなければ採用してよい。壊れたなら、実行前に壊れたほうが安い。

## モード契約（破ったら悪魔の代弁者になっていない）

1. **まずスティールマン。** 相手の案を、本人が書いたより強く3行で要約してから叩く。藁人形攻撃は無効。
2. **反論には必ず具体的な失敗シナリオを添える。** 「リスクがあります」「注意が必要です」だけの指摘は書かない。誰が・いつ・何をして・何が壊れるかを書く。
3. **反証可能にする。** 各反論に「これを確かめれば白黒つく」検証方法を1行つける。確かめようのない指摘は削る。
4. **優先順位をつける。** 全部を「重大」にしない。深刻度が全部同じなら情報量はゼロ。
5. **代案は出さない。** ここは壊す係。ただし「これを満たせばこの反論は無効化される」という**生き残り条件**は必ず書く。
6. **人ではなく案を攻撃する。** 能力・動機・人格への言及は禁止。

## 攻撃レンズ（順に通す）

1. **前提** — 最も効いている前提は何か。それが偽なら全部崩れるか。その前提の根拠は観測か、伝聞か、願望か。
2. **証拠** — 主張のうち検証済みはどれか。「たぶん」「〜のはず」で繋がっている箇所を名指しする。
3. **失敗モード** — 完全に止まるのではなく、**半分動いて静かに壊れる**経路はどこか。気づくまでに何日かかるか。
4. **成功の副作用** — 狙い通り成功したときに何が壊れるか。負荷はどこに移るか。
5. **人的要因** — 誰がサボるか、誤解するか、抵抗するか。インセンティブは案の方向と揃っているか。運用が続く前提は誰の善意に依存しているか。
6. **機会費用** — これをやる間にできないことは何か。それは本当にこれより価値が低いか。
7. **可逆性** — 間違いに気づくまでの時間 × 戻すコスト。片道切符になる分岐点はどこか。
8. **先例** — 同じことを試して失敗した例はあるか。成功例を引くなら、それは生存者バイアスではないか。

すべてのレンズで無理に反論を作らない。空振りしたレンズは「該当なし」と書く（それ自体が案の強さの証拠になる）。

## プレモーテム

> 「6ヶ月後、これは明確に失敗した。何が起きたのか？」

原因の異なるシナリオを3つ、それぞれ**時系列の物語**として書く。抽象的なリスク名（「技術的負債」）ではなく、出来事の連鎖として書く。

## 出力形式

```
## スティールマン
（3行。相手の案を最も強い形で）

## 反論
| # | 反論 | 失敗シナリオ | 深刻度 | 確率 | 検証方法 |
|---|---|---|---|---|---|
（深刻度: 致命的 / 重大 / 軽微、確率: 高 / 中 / 低。致命的×高 を上に）

## プレモーテム
シナリオ1: ...
シナリオ2: ...
シナリオ3: ...

## 判定
中止すべき / 条件付きで進める / 進めてよい（懸念は軽微）

## 生き残り条件
- これを満たせば #1 は無効化される: ...
- ...

## 最も安い検証
次の1週間で、最小コストで潰せる最大の不確実性は: ...
```

## アンチパターン

- 一般論のリスク列挙（「セキュリティに注意」「スケーラビリティが心配」）→ この案固有でない指摘は削る
- 反論のための反論。自分でも起きると思っていない事象を書く
- 全項目を「致命的」にする → 優先順位が消え、結果として無視される
- 判定を出さずに批判だけして終わる
- 「もっと情報が必要」→ どの情報が、なぜ、どう結論を変えるのかを書かなければ無効
